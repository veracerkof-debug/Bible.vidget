# Состояние работы

Обновлено: 19.11.2026.

## Сделано (v0.1, проверено)
* Ядро: серии, модель из файлов, клиент GitHub, локальная копия + очередь записи (офлайн, повтор, порядок «фото → отчёт»).
* Экраны: вход (язык → профиль → создать пару / присоединиться), главная (серии, неделя, два отчёта дня, «прочти», молитва, памятные дни),
  Библия (Синодальный/KJV/WEB/AYT, выделение, заметка, отправка стиха, жест смахивания глав), лента, история-календарь, профиль и настройки,
  уведомления (мастер настройки для создателя).
* Серверная часть уведомлений (`tools/notify*.mjs`, `data-template/notify.yml`) — логика покрыта тестами, запуск проверен на тестовом репозитории (`--dry`).
* Проверено: 31 модульный тест; сквозной прогон (`node tests/e2e/run.mjs`) — два «телефона» с фальшивым GitHub проходят весь путь до совместной серии.

## Не проверено на настоящих сервисах (ждёт автора)
1. **Настоящий GitHub**: создание организации, токена, записи и чтения по настоящему API (в тестах — точная имитация нужных запросов).
   Риск: поведение `git/trees/<ветка>` в только что созданном пустом репозитории и права токена организации.
2. **Web Push**: ни разу не отправлялся настоящий пуш. Проверить цепочку: ключи → секрет → workflow → подписка на телефоне → пуш при отчёте партнёра.
3. **iPhone**: установка на экран «Домой», камера (`capture`), push. Android — то же самое на живом устройстве.
4. Публикация: включить GitHub Pages (Source: GitHub Actions) — workflow `pages.yml` в репозитории.

## Известные ограничения / идеи
* Нумерация псалмов Синодального перевода отличается от KJV/WEB/AYT.
* Расписание GitHub Actions неточное (напоминание может опоздать до получаса).
* Не сделано из примера: «ставка», виджеты, групповые пары (только двое), голосовой ввод, учебный режим «Study», недельные итоги-видео.
* Идеи: планы чтения (из Melete `core/reading.js`), «живая» камера с превью, закрепление стиха дня, экспорт всех данных в один архив.
